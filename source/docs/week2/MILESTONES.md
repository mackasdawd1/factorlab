## Checkpoint 1 当周细分

- Sep 21：将已准备的 SVG 导入 Figma，重建必要可编辑组件与输入状态；检查文本字体、frame 名称与顺序。
- Sep 22：连接主旅程、六轮、错误态、回测返回与 Coach fallback；确认没有断头屏。
- Sep 23：用测试脚本邀请至少 3 位目标用户（建议样本目标，当前参与数为 0）；记录任务完成、提示次数、概念误解。
- Sep 24：修复 blocker/high 级问题，保留改前/改后 evidence；重新走查六轮。
- Sep 25：固定 Figma version、导出截图/短视频与 checkpoint 摘要。实际作业提交由用户完成。

## 持续证据规则

每个里程碑保留：日期、版本/commit（没有就写无）、环境、任务步骤、预期/实际、结果、缺陷与修复、截图/视频链接。结果用 PASS / FAIL / NOT RUN；计划不能填写为 PASS。

每周日志可直接复用 progress.md 与对应 evidence，不事后伪造访谈、性能数字、测试通过数或统计显著性。反馈只记录参与者代号与必要匿名意见，不收集真实财务信息。

责任假设：由同一小团队承担设计/开发/财务校验，用户负责课程要求确认、Figma 账户/分享及正式提交；团队人数未提供，不虚构工时承诺。

## 收缩顺序

先删动画、复杂主题、真实数据扩展、自由聊天、多场景、导出美化；保留六轮旅程、四因子、回测/有效性、七项 Dashboard 与解释 Coach。到 Week 8 后不改核心状态模型或计算口径，除非修正确定的金融错误，并补回归证据。
